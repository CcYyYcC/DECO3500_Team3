# DECO3500 初版原型测试：综合采访总结

**原型：**蓝色学习 Token 与 Tower  
**参与者：**P01、P02、P03  
**测试方式：**每人模拟两次学习；8 秒代表 1 小时。本轮只测试了学习 Token。


### 证据来源

本总结结合了 `P01.pdf`、`P02.pdf`、`P03(1).pdf` 中已勾选的现场观察表，以及此前校正过中文原话的 P01–P03 采访转录。PDF 第 3–4 页的采访记录栏基本为空：下文的数量来自观察表，采访观点来自校正后的转录。三次测试都是短时形成性测试，只能反映参与者当场的理解与预期，不能证明长期使用后游戏行为会改变。

### 三位参与者的情况

| 参与者 | 观察表记录 | 采访中值得注意的回答 |
| --- | --- | --- |
| **P01** | 第二次能独立翻转；Token、Tower 均勾选“清楚”；一小时和两小时勾选“回答正确”。 | 将 Token 的点理解为时间流逝，认为装置“不灵敏”。若室友也能看见 Tower，表示可能只记录学习、不记录游戏。虽然观察表记为答对时长，自发解释中又提到“三个小时的睡觉时间”，活动与时长的对应关系仍值得复测。 |
| **P02** | 第二次能独立翻转；Token、Tower 均勾选“清楚”；一小时和两小时勾选“回答错误”。 | 起初没有顺利启动 Token。认为 Token 显示任务进度、Tower 统计完成的单位，但希望时长更明确，例如通过调整方块长度来表示时间；也询问多人记录如何区分。 |
| **P03** | 第二次能独立翻转；Token 勾选“部分清楚”，Tower 勾选“清楚”；一小时和两小时勾选“回答正确”。 | 将初始图标理解为等待或沙漏状态，但觉得单条进度线不够直观。经解释后理解一个方块是一小时，起初不明白堆叠的意义；认为每小时都要翻一次会很麻烦。 |

三份观察表均记录第二次可以独立翻转（**3/3**）；Token 被勾选“清楚”的有 **2/3**；一小时、两小时回答正确的有 **2/3**。Tower 的累计意义虽然在观察表上全部勾选“清楚”（**3/3**），采访中仍出现对具体时长和堆叠意义的不确定。因此报告结果时应同时呈现勾选结果与原话，避免直接写成“三人都完全理解 Tower”。

### 主要发现

1. **Token 记录、Tower 累积的基本关系能够被识别，但触发不够稳定。** 参与者大致把 Token 看成进度提示，把 Tower 看成已完成活动的记录。P01 觉得 Token 不灵敏；P02 翻转 180 度后没有看到预期进度；P03 也遇到过未成功触发的情况。反应不稳定会让人难以判断是自己操作错误，还是界面表达不清。

2. **图形逐渐堆叠，不代表用户就能准确读出时长。** P02 理解“会增加方块”，但观察表记录其一小时、两小时回答错误。P03 在主持人说明后理解“一个方块是一小时”，却表示原先不清楚方块堆起来代表什么。Tower 需要更清楚地呈现单个单位、活动类别和累计总量。

3. **Token 的不同状态需要更明确。** 参与者提到点数、进度条和落下的图形，但 P03 对初始图标的含义不够确定，并建议用逐渐扫过的面积或转动来表达进度。P02 希望直接看到时间，P01 希望翻转后的反应更灵敏。等待、计时中、完成三个状态应能被直接区分。

4. **公共展示会影响记录意愿。** P01 表示可能只展示学习，隐藏游戏，甚至假装在学习。P02 认为公共展示可能形成一定监督，也担心比较压力，希望不同用户分开显示。P03 对室友的数据兴趣不大，有隐私顾虑，并认为能否比较取决于大家是否处于相似的学习情境。这些回答针对的是**假设的多人使用场景**；本轮硬件没有实际展示多人记录。

5. **每小时操作一次可能妨碍长期使用。** P03 认为每小时回来翻 Token 不现实；P02 也提出不同任务时长如何体现的问题。P03 表示看见较长游戏时间或许会让自己意识到玩得久，却不会仅因此停止游戏。目前证据更能支持“帮助反思时间使用”，不足以证明“减少游戏时间”。

### 下一版优先考虑

| 优先级 | 可探索的修改 | 下次测试要验证什么 |
| --- | --- | --- |
| 1 | 提高翻转识别的稳定性，并立即反馈“已开始”。 | 新用户无需主持人解释，能否判断已启动；记录失败与重复翻转。 |
| 2 | 区分 Token 的等待、计时中和完成状态。 | 用户能否说出各状态的含义及结束时机。 |
| 3 | 明确 Tower 每个单位代表一小时，并显示累计总量。 | 模拟一小时、两小时后，用户能否无需提示说出总量并解释堆叠。 |
| 4 | 探索开始和结束各操作一次的记录方式，支持多小时活动。 | 用户能否记录连续数小时的学习或游戏，而无需每小时返回操作。 |
| 5 | 先制作私人／共享模式和分开的用户列，再测试社交效果。 | 用户愿意公开哪些活动，以及能否分辨每个人的记录。 |

**研究边界：**只有三位参与者、一种蓝色学习 Token、两次压缩计时，没有长期跟踪。社交问题是基于想象的共享 Tower；观察表的大部分自由填写栏和采访栏为空，因此主题分析依赖已校正的采访转录。本轮没有 SUS 分数，也没有临床效果证据。
